# Отчет

## 1. Сравнение времени выполнения
| Размер входа (N) | Futures | Coroutines |
| :--- | :--- | :--- |
| **100,000 (10^5)** | 0.00844974s | 0.0143476s |
| **1,000,000 (10^6)** | 0.088812s | 0.0624973s |

## 2. Оценка памяти
**Futures-модель:** Требует аллокации и хранения полных векторов на каждой стадии. При $N=10^6$ один вектор `double` занимает около 8 МБ. Между стадиями Load и Transform в памяти могут находиться сразу два таких вектора (пик ~16 МБ).

**Coroutine-модель:** Работает по принципу «ленивых вычислений». Элементы генерируются и обрабатываются по одному. Пиковая память минимальна и практически не зависит от $N$, так как весь массив целиком в памяти не хранится.

## 3. Короткие выводы (5–10 предложений)
Futures-модель (`std::async`) проще в реализации для простых цепочек задач, так как она использует стандартный `std::move`.

Корутины выигрывают в читаемости основного цикла обработки, так как код выглядит как обычный итератор. Корутины значительно превосходят futures-модель при обработке больших объемов данных, так как исключают создание промежуточных векторов.

В futures-модели узким местом является потребление RAM при росте $N$. В корутинах узким местом может стать производительность самого итератора.
