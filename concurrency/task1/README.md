# Сборка
```bash
g++ -std=c++20 1.cpp -lpthread -o task1

./task1
```
# Отчёт
На малых объемах данных многопоточная версия показывает отрицательное ускорение. Это обусловлено накладными расходами на создание потоков и искусственной задержкой в 100 мс, необходимой для корректного отображения статуса отсоединенного потока-индикатора. В реальных задачах для таких объемов данных параллелизм нецелесообразен.

При достижении миллиона строк вычислительная нагрузка начинает преобладать над расходами на управление потоками. Полученное ускорение 1.71x подтверждает эффективность параллельной обработки.

Узкие места: Основным ограничителем скорости является синхронизация при работе с `std::set<int>`. Операция вставки уникальных `user_id` из локальных результатов потоков в общий агрегатор требует блокировки мьютекса, что превращает эту часть программы в последовательную.
